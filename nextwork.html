Automating the module-writing process

Every learning module NextWork publishes is now written by a multi-stage LLM orchestration pipeline I built.

  1. Brainstorming. Decide what a project or module should be about.
  2. Staged research. Gather material through MCP tools: Firecrawl, Exa, Context7.
  3. Compilation. Build the module by applying a large set of defined rules with conditional content logic. If the module covers X then it must do Y; if it does Y then it must show Z; if it shows Z then it must use wording W.

Different models run at different stages, chosen mainly for cost and speed. The output is a block-structured JSON file, compiled and served to the web page. The compiler started in Python, then moved to C/C++ and Go once the design was stable.

I wrote the modules by hand first. About twenty of them, over six months, before automating anything. The point was to establish what a good module looked like, so the pipeline had a real standard to hit rather than an imagined one.

Results

  • Writing a module went from 7+ days to under 1 day.
  • 20+ modules produced by the pipeline within the first three months, 50+ since.
  • Weekly active user growth went from flat to roughly 15% month on month.

Every module still passes a review before publish. It is read by everyone who builds downstream social content from it, and by the CEO.
