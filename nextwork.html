Automating the module-writing process

Every module NextWork publishes now comes out of a multi-stage LLM pipeline I built.

  1. Brainstorm what the module should be about.
  2. Research in stages through MCP tools (Firecrawl, Exa, Context7).
  3. Compile the module against a big rule set. If it covers X it must do Y, if it does Y it must show Z, if it shows Z it uses wording W.

Different models at different stages, picked for cost and speed. Output is block-structured JSON, compiled and served to the page. The compiler started in Python and moved to C/C++ and Go once the design settled.

I wrote about twenty modules by hand first, over six months, before automating anything. That set the bar for what a good module looked like, so the pipeline had a real standard to hit.

Results

  • Writing a module went from 7+ days to under 1 day.
  • 20+ modules produced by the pipeline within the first three months, 50+ since.
  • Weekly active user growth went from flat to roughly 15% month on month.

Every module still gets reviewed before publish, by everyone building social content from it and by the CEO.
