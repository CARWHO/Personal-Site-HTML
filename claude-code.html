How I use Claude Code

Two Obsidian vaults and a set of code repos, each a Claude Code working directory, each with different rules. The rules are different on purpose. The question I ask in each place is what would be lost if the machine did the work, and the answer decides how much it is allowed to do.

The personal vault

A knowledge base: notes, learnings, and reference material from books, companies, and technical topics. Book notes and active-recall files. Go learning notes. System design write-ups. One folder per business idea. Meeting notes, career, an inbox.

Two conventions do most of the work:

Notes are markdown files, often in active recall format (question, then ?, to test yourself).

Book notes should capture rules and principles, not summaries.

That second line is the whole philosophy.

digest-book

A skill that takes a non-fiction book PDF, extracts the full text, and writes a summary. Then it stops.

The principle: you skip reading the whole book. You read the summary, then write the page from it in your own words. That rephrasing is the encoding step that builds memory, so the skill never writes the write-up for you.

The write-up file is protected. There is a guard script in the skill whose only job is to refuse to overwrite it. The skill also warns before digesting a narrative book, where pulling out ideas is the wrong altitude. Python, PyMuPDF, forty deterministic tests. Everything on the books page came out of this loop.

disciplined-entrepreneurship

A skill that checks a business idea against the Disciplined Entrepreneurship framework, wired into the ventures folder as the rule set every new idea gets run through. It is the book write-up turned into a tool.

The university vault

A separate vault, separate rules. Its instructions open with:

The goal is marks with minimum reading.

And then, more importantly:

This agent is for learning, lecture compression, revision, mistake detection, and course facts. Do not organise or complete current graded assessments.

The rest is mostly restraint. Chat only by default, and no changes to the vault without confirmation. Never invent assessment dates, requirements, scope, or lecturer expectations. No study schedules unless asked. Prefer deleting information over organising irrelevant information. Any generated note must be materially faster to read than its source.

There is a memory rule: when I mention a recurring mistake or a confirmed course fact, it asks one short question, whether to add it to the mistakes file, and does nothing until I say yes.

And one rule about teaching:

When explaining a concept the user is struggling to visualise, lead with a concrete physical analogy, then map each real component onto its counterpart in the analogy. Pick an analogy from mechanics, fluids, or everyday objects, something with visible moving parts.

The worked example in the file is an RCD turn-off snubber explained as water hammer. Current is water in a pipe. Inductance is its momentum. The switch is a valve. The snubber capacitor is an air chamber the water compresses as it coasts to a stop. The diode is a one-way flap. The resistor is a slow bleed valve. The analogy and the real circuit stay explicitly paired.

The code repos

HireOS carries the heaviest setup. Project instructions, a context document that defines the domain vocabulary with banned synonyms, a design document of canonical UI rules, eighteen architecture decision records, and twenty custom skills. Nine of the skills are audits: API, security, performance, React, data, ops, reliability, TypeScript, and general code. The rest are workflow: test-driven development, triage, diagnose, turning a conversation into a PRD, turning a PRD into issues, zooming out, grilling a change against the docs, and improving codebase architecture. Six git worktrees so several agents can work in parallel without treading on each other.

Three settings

The two vaults have opposite rules and that is the point. The personal vault's skill refuses to write my book notes for me, because the writing is the learning. The university vault refuses to touch graded work and defaults to chat rather than files, for the same reason plus an integrity one. The code repos go the other way entirely: heavy automation, audit skills, parallel worktrees, because there the output is the point and I can verify it.

Same tool, three settings, chosen by asking what would be lost if the machine did it.
